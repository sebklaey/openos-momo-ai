Model Context Protocol · lokal-first

OpenOS Momo AI — MCP-Endpunkt

Offizielle URL: https://openos.kimi.page/ · Maschinenlesbares Manifest: /mcp.json · SDK: /momo-sdk.js

Architektur-Entscheidung: OpenOS Momo AI betreibt bewusst keinen zentralen POST /mcp-Server. Die drei Werkzeuge werden auf dem Gerät des Aufrufers ausgeführt — dieselbe Engine, dieselben Gewichte, dieselbe Logik wie in der App. /mcp.json spezifiziert die Werkzeugliste und Schemata nach MCP-Konventionen, damit KI-Clients die Semantik maschinell lesen können.

Werkzeuge

bitseed_compress

Verlustfreie Kompression (Bitseed Engine v4: adaptive Kontextmodelle, LZP-Match, Perzeptron-Mischer, APM, binäre arithmetische Residual-Kodierung). Jede Ausgabe trägt einen SHA-256-Fingerabdruck der Eingabe.

SDK: const c = await momo.compress(bytes) → { archive, ratio, sha256, engine }

bitseed_decompress

Dekompression, bit-exakt. Der zurückgelieferte SHA-256 muss mit dem Wert aus bitseed_compress übereinstimmen.

SDK: const r = await momo.decompress(c.archive) → { data, sha256, engine }

momo_chat

Chat mit Momo AI (Saiten-148M: 148M Parameter, Deutsch + Englisch, on-device). Lädt die Gewichte (142 MB) einmalig, hält sie im Speicher, Sessions pro Schlüssel, Kontextfenster 512.

SDK: const a = await momo.chat("Was bist du?") → { text, stats }

Schnellstart (Node 18+ / Browser)

const MomoAI = require("https://openos.kimi.page/momo-sdk.js"); // oder <script src=".../momo-sdk.js">
const momo = await MomoAI.create();            // kein Key, kein Server
const c = await momo.compress(daten);          // → { archive, ratio, sha256 }
const r = await momo.decompress(c.archive);    // bit-exakt, sha256 prüfbar
const a = await momo.chat("Was bist du?");     // 148M-Modell, einmalig laden
